# Internationalisation

[Overview](index.md) · Details: [localization.md](localization.md) · Error codes: [error-codes.md](error-codes.md)

**Milestone:** v0.13. German and English apply to the HTML admin, the standard page texts and the central CLI success messages. English is the default language and the technical fallback for newly generated projects and configurations without an explicit locale. Projects that explicitly set `default_locale = "de"` remain German. The Cargo version is `0.1.2`.

## Responsible files

- `crates/fexu-admin/locales/en.po` and `crates/fexu-admin/locales/de.po` contain the bundled admin UI catalogues. `crates/fexu-admin/src/localization.rs` reads the embedded catalogues through `include_str!`; the requested locale never becomes a file path.
- `POST /admin/preferences` stores `fexu_locale` as an HttpOnly cookie. The document sets `lang`.
- `crates/fexu-api/src/pages.rs` selects the Tera language of the project pages.
- `crates/fexu-cli/src/text.rs` translates the central CLI lines.

## Data flow

1. Without a cookie, `Accept-Language` applies, then `default_locale`, then `fallback_locale`.
2. The language form sends `de` or `en`. Another value remains with the current language. The next GET page shows the new language.
3. The admin catalogues are built into the crate at compile time; no language download is required. English is the source/fallback, and the existing German strings are retained in `de.po`.
4. Validation display goes through `fexu_core::message_text`. German is used only for `de`; every other locale uses English. A missing code returns `missing message`. SQL, stack traces and `password_hash` become the generic rejection text.

## Limitations and planned expansion

The bundled admin catalogue and the CLI catalogue are English by default. German is the explicit `de` locale, including `FEXU_LOCALE=de` for the CLI. This does not translate app or model labels, database records, or choice text stored on rows. Developer diagnostics are English unless the locale is `de`. `fexu migrate` follows that rule, so older German diagnostic sentences are not stable script output. The PO loader recognizes the bundled `en` and `de` catalogues only; further locales require a reviewed catalogue and a locale allowlist update. The admin locale cookie, language switch and fallback behavior remain unchanged.

See the [internationalization architecture RFC](i18n-architecture.md). Step 2 of that RFC (English-first diagnostics) is partial. Steps 3–6, including translatable labels and records, are not implemented. [Issue #148](https://github.com/Iam-Sanja/fexu-rs/issues/148) tracks that remaining work.
